# Development Diary - August 2026

---

## 2026-08-05: Move iOS release CI to hosted macOS

Changed the manually dispatched iOS release workflow to use
`macos-latest`. The public repository can use GitHub-hosted macOS runners,
so TestFlight and App Store release jobs no longer wait for a self-hosted
runner to be online. Also aligned its vcpkg checkout with the valid,
project-declared dependency baseline after the previous malformed pin failed
to check out on the hosted runner.

---

## 2026-08-04: Make the iOS release path non-interactive

Converted the iOS release workflow from a push-triggered TestFlight upload to
an explicit dispatch with separate TestFlight and App Store-review paths.

- Match now uses read-only signing assets from the organization store through
  a basic-auth token.
- App Store Connect uses a Base64-encoded team API key; no Apple ID session is
  required on the runner.
- TestFlight builds use the GitHub Actions run number as `CFBundleVersion`.
- App Store submission selects an already processed TestFlight build and only
  enables automatic release when explicitly requested.
- App repositories mint a short-lived, repository-scoped GitHub App token to
  clone the private Match store instead of carrying a long-lived Git token.
