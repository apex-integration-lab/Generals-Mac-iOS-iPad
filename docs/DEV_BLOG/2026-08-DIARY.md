## 2026-08-06: Fix Fastlane generated project lookup

Checked the latest iOS release workflow run after fast-forwarding `main`.
The hosted runner completed checkout, dependency setup, Match signing sync,
CMake configure/build, MoltenVK fetch, font staging, and XcodeGen, then failed
when Fastlane's `increment_build_number` could not resolve the generated
`GeneralsXZH.xcodeproj`. Updated the TestFlight lane to keep a repo-root
constant, pass an absolute Xcode project path into Fastlane/Xcode build
steps, and fail explicitly if XcodeGen does not create the expected project.

Follow-up: the next TestFlight dispatch got past the generated-project lookup
and into Xcode, but the runner sat in the Xcode `CodeSign` phase for the
generated shell app until the run was canceled. Changed the lane to build the
shell wrapper unsigned, embed the exact Match provisioning profile, extract
entitlements from that profile, and use the existing manual signing step for
the final assembled app. This avoids relying on the Xcode CodeSign phase that
was hanging before IPA packaging/upload.

## 2026-08-05: Move iOS release CI to hosted macOS

Changed the manually dispatched iOS release workflow to use
`macos-latest`. The public repository can use GitHub-hosted macOS runners,
so TestFlight and App Store release jobs no longer wait for a self-hosted
runner to be online. Also aligned its vcpkg checkout with the valid,
project-declared dependency baseline after the previous malformed pin failed
to check out on the hosted runner. Pinned the consuming Matchfile to the
`main` storage branch as well; without it, Fastlane defaulted to the empty
legacy `master` branch and could not install the stored signing identity.
Corrected the TestFlight lane's working directory too: Fastlane evaluates it
from `fastlane/`, while the CMake, XcodeGen, and packaging paths are rooted at
the repository root. Removed output pipes that previously hid CMake/Xcode
failures from the workflow.

Configured TestFlight uploads to wait for build processing and target the
existing internal tester group, `Aaron`. This keeps external distribution off
while ensuring successful CI uploads are made available to that group.
Keep the Match synchronization outside the repository-root build block so
Fastlane continues to resolve `fastlane/Matchfile` and its `main` storage
branch before CMake/XcodeGen commands run from the project root.

Added hosted-runner caches for Homebrew downloads, vcpkg setup, and C/C++
compiler objects. The first successful build populates them; subsequent builds
reuse bottles, package artifacts, and unchanged compilation outputs.

Updated the vcpkg baseline to the revision that contains the lockfile's FFmpeg
8.1.1#2 entry. The previous baseline only provided FFmpeg 7.1 and stopped CMake
before compilation began.

## 2026-08-04: Make the iOS release path non-interactive

Converted the iOS release workflow from a push-triggered TestFlight upload to
an explicit dispatch with separate TestFlight and App Store-review paths.

- Match now uses read-only signing assets from the organization store through
  a basic-auth token.
- App Store Connect uses a Base64-encoded team API key; no Apple ID session is
  required on the runner.
- TestFlight builds use the GitHub Actions run number as `CFBundleVersion`.
- App Store submission selects an already processed TestFlight build and only
  enables automatic release when explicitly requested.
- App repositories mint a short-lived, repository-scoped GitHub App token to
  clone the private Match store instead of carrying a long-lived Git token.
